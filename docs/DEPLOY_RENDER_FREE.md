# GitHub -> Render Free Deployment Profile

Status: hobby/development deployment profile. It intentionally makes no 24/7 production availability claim.

## Topology

- GitHub: source repository and CI.
- Render Free Web Service: Node.js platform process (`PROCESS_ROLE=all`) containing HTTP API, Discord Gateway client, durable worker loop, and realtime WebSocket endpoint.
- Render Static Site: React/Vite operator dashboard.
- Supabase Free: recommended durable PostgreSQL and optional Storage provider for the zero-mandatory-cost profile.

## Why the database is external in the default free profile

Render Free Postgres is not selected by `render.yaml`. Render documents that its free Postgres instances expire after 30 days and do not include backups. The free web filesystem is ephemeral, so SQLite/local uploads are not durable either. The default profile therefore expects a separately supplied `DATABASE_URL`, with Supabase Free as the recommended zero-cost option.

Official references:
- https://render.com/docs/free
- https://render.com/docs/blueprint-spec
- https://supabase.com/pricing

## Required secrets

Set these in Render, never in Git:

- `DISCORD_BOT_TOKEN`
- `DISCORD_APPLICATION_ID`
- `DATABASE_URL`
- optionally `DISCORD_TEST_GUILD_ID`
- optionally `SUPABASE_URL`
- optionally `SUPABASE_SERVICE_ROLE_KEY`

`ADMIN_API_KEY` and `INTERACTION_SIGNING_SECRET` are generated by the Blueprint when absent.

Also set:

- API service `DASHBOARD_URL` = public static-site URL
- API service `DASHBOARD_ORIGIN` = same public static-site origin
- Static site `VITE_API_BASE_URL` = public API web-service URL

## Deploy

1. Push this repository to GitHub.
2. Create a Supabase Free project and obtain a PostgreSQL connection string.
3. In Render choose **New -> Blueprint** and connect the GitHub repository containing `render.yaml`.
4. Supply the `sync: false` secret values during the initial Blueprint creation.
5. Set the cross-service public URLs listed above once Render assigns service URLs.
6. Confirm the web service readiness endpoint returns HTTP 200 from `/ready` only when required DB/Discord/worker dependencies are ready; `/health` remains diagnostic.
7. Copy the generated `ADMIN_API_KEY` into the dashboard's Operator key field when privileged guild event streaming is required. The browser stores it only in `sessionStorage` and sends it as a Bearer header / WebSocket auth frame, not in the bundled source.
8. Use a Discord test guild first, run `/setup` dry-run, inspect the plan, then apply.

## Free-tier limitations that cannot be designed away

Render Free web services spin down after 15 minutes without inbound HTTP requests or inbound WebSocket messages. They can take roughly a minute to wake. Each workspace receives a monthly free-instance-hour allocation. The platform deliberately does not include artificial keepalive traffic to evade these constraints.

This matters for a Discord Gateway bot: a free Render deployment is suitable for development/hobby validation, but it is not an honest 24/7 bot availability guarantee. The code keeps process roles portable so a later always-on host can run the same business modules without a rewrite.

Supabase Free also has quotas and inactivity behavior. Capacity and backup requirements must be reassessed before production maturity can pass Level 5.
